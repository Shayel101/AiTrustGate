# Evidence Ledger

This ledger tracks every important factual claim used in this project's
documentation, where it came from, and whether it has been independently
verified against the original source (not against AI-generated output).

## Claim 1: JBB-Behaviors contains 100 harmful and 100 benign behaviors, thematically paired

- **Source type:** Peer-reviewed/academic
- **Source:** Chao et al., "JailbreakBench: An Open Robustness Benchmark for
  Jailbreaking Large Language Models," NeurIPS 2024 Datasets and Benchmarks
  Track (arXiv:2404.01318); dataset card at
  huggingface.co/datasets/JailbreakBench/JBB-Behaviors
- **Evidence/observation:** Fetched the official dataset CSV files and
  repository README directly; counted 100 rows in each of
  `harmful-behaviors.csv` and `benign-behaviors.csv`.
- **Why it matters:** Confirms the dataset size and structure this project
  relies on (200 total examples).
- **Independently verified?** Yes — checked row counts in the downloaded CSVs
  and cross-checked against the JailbreakBench GitHub README description.

## Claim 2: JBB-Behaviors sources harmful examples from AdvBench, TDC/HarmBench, and originally-authored prompts, categorized per OpenAI's usage policies

- **Source type:** Peer-reviewed/academic

## Claim 6: A TF-IDF + Logistic Regression baseline achieves ~0.73 accuracy / ~0.80 recall for the harmful class on this 200-example split

- **Source type:** Project-generated (not third-party)
- **Source:** This repository: `results/metrics.json`, produced by
  `python src/train.py`.
- **Evidence/observation:** Metrics file generated by actually executing the
  training/evaluation script with `random_state=42`.
- **Why it matters:** This is the central technical result of the A1
  prototype and must be reproducible, not asserted.
- **Independently verified?** Yes — verified by re-running
  `python src/train.py` and confirming `results/metrics.json` matches the
  reported numbers.

## Claim 7: 5-fold cross-validation on the training split alone averages only ~0.54 accuracy, near chance level for this balanced task

- **Source type:** Project-generated (not third-party)
- **Source:** This repository: `results/metrics.json` fields
  `cv_accuracy_mean` / `cv_accuracy_folds`, produced by `python src/train.py`.
- **Evidence/observation:** Computed directly via
  `sklearn.model_selection.cross_val_score` on the training split only, never
  touching the test set.
- **Why it matters:** Shows the single fixed 80/20 split is comparatively
  favorable and that this negative result should not be hidden; grounds the
  decision not to chase >80% accuracy by overfitting the fixed split.
- **Independently verified?** Yes — verified by re-running
  `python src/train.py` and confirming the reported CV numbers.

## Notes

- Copilot/ChatGPT output is never treated as a source in this ledger; only
  the original academic paper, dataset repository, or NIST publication (or
  this project's own executed code) count as evidence.
- Numeric claims about the classifier's performance are drawn solely from
  `results/metrics.json` and `results/evaluation.txt`, generated by running
  `src/train.py`, not from memory or estimation.
